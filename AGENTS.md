# AGENTS.md — Bboard Project Rules

## 1. Обзор и документация
- **Стек:** Go 1.22+ (стандартный `net/http` с `ServeMux` паттернами), PostgreSQL 16 (`jackc/pgx/v5`), `golang-jwt/jwt/v5`, `sirupsen/logrus`[cite: 3], фронтенд — Zero-Build Vanilla ES6+ SPA (`web/`) без сборщиков[cite: 4].
- **Детальная архитектура:** Перед крупным рефакторингом или созданием новых сущностей изучай `BACKEND_ARCHITECTURE.md` и `FRONTEND_ARCHITECTURE.md` в корне проекта.

## 2. Правила Go Backend (Clean Architecture & DDD)
- **Dependency Rule (строго):** `domain` не импортирует ничего внешнего (ни `pgx`, ни `net/http`, ни JSON-теги)[cite: 3]. `usecase` зависит только от интерфейсов из `domain` и `pkg/token`[cite: 3].
- **Богатая доменная модель:** Валидация полей и переходы статусов (например, `open -> in_progress -> completed/canceled`) инкапсулируются внутри методов сущностей (`domain/*/entity.go`), а не в хэндлерах[cite: 3].
- **Обработка ошибок:** Используй типизированные ошибки из `domain/*/errors.go` и проверяй их через `errors.Is()` в HTTP-хэндлерах для возврата корректных кодов (400, 401, 403, 404, 409)[cite: 3]. Нарушения уникальности БД (`SQLSTATE 23505`) перехватывай в `repository/postgres` и маппь в доменные ошибки[cite: 3].
- **Безопасность HTTP:** Используй `http.MaxBytesReader` и `DisallowUnknownFields()` при декодировании входящего JSON[cite: 3].
- **Миграции:** Любое изменение схемы БД оформляй парой файлов `migrations/00000X_name.up.sql` и `.down.sql`[cite: 3].

## 3. Правила Frontend (`web/`)
- **Без сборщиков и фреймворков:** Не добавляй `npm`, Webpack, Vite, React или сторонние CDN-скрипты[cite: 4]. Используй нативные ES6-модули (`import`/`export`)[cite: 4].
- **Поток данных:** UI-компоненты (`web/js/components/`) не вызывают `fetch` напрямую — все запросы идут только через `web/js/api/httpClient.js`, а состояние обновляется через `store.setState()` (`web/js/store/store.js`)[cite: 4].
- **Безопасность и стили:** Весь пользовательский ввод перед вставкой в DOM обязательно экранируй через `escapeHtml()`[cite: 4]. Новые стили пиши в `web/css/styles.css` с использованием существующих CSS-переменных (`:root`)[cite: 4].

## 4. Команды проверки и стиль работы
- **Согласование правок:** Перед каждым изменением или созданием файла показывай предлагаемый код/diff и запрашивай подтверждение пользователя.
- **Проверка после правок Go:** После изменения `.go` файлов всегда запускай `go build ./...` и `go vet ./...` для проверки компиляции.
- **Локальная БД:** Поднимается через `docker-compose up -d` (PostgreSQL + автонакатка миграций).
- **Язык общения:** Отвечай на русском языке, комментарии в коде и сообщения об ошибках API пиши в едином стиле с существующей кодовой базой.
