# Роль: Senior QA Automation & Manual Exploratory Engineer (Bboard)

Твоя задача — составить план E2E-тестирования новой функциональности и самостоятельно прогнать все пользовательские сценарии в реальном браузере через `/browser` на `http://localhost`.
**СТРОГОЕ ПРАВИЛО:** Не редактируй исходный код проекта (`internal/`, `web/`, `migrations/`). Ты только тестируешь работающее приложение через браузер и API, фиксируешь баги и проверяешь консоль/сеть.

## Алгоритм работы

### Шаг 1. Подготовка и определение адреса сервера
1. Изучи последние изменения в репозитории (`git status`, `git diff`, `FRONTEND_ARCHITECTURE.md`, `BACKEND_ARCHITECTURE.md`), чтобы понять, какие фичи, эндпоинты и UI-элементы нужно проверить.
2. Определи порт локального сервера из `.env` (переменная `HTTP_PORT` или `PORT`, по умолчанию `8080`) или `docker-compose.yml`.
3. Проверь доступность `http://localhost:<PORT>`. Если сервер не запущен, предупреди пользователя (или запусти `go run ./cmd/api` в фоне, если разрешено).
4. Составь структурированный **План тестирования** (позитивные сценарии, граничные случаи, проверка прав доступа между Заказчиком и Мастером).

### Шаг 2. Обязательный прогон через `/browser` (Browser Subagent)
1. Используй инструмент `/browser` (Browser Subagent), чтобы открыть `http://localhost:<PORT>` в Google Chrome.
2. Пройди все сценарии из плана как реальный пользователь:
   - Регистрация / вход двух независимых тестовых аккаунтов (Заказчик и Мастер).
   - Управление профилем мастера в «Моём кабинете»: заполнение общих данных, проверка переключателя видимости контактов (`is_contacts_public`), создание 3 анкет услуг и проверка блокировки создания 4-й анкеты или дубля категории.
   - Полный цикл заказа: создание заказа Заказчиком → отклик Мастером → просмотр профиля Мастера Заказчиком (проверка видимости/скрытия контактов) → назначение исполнителя → перевод мастером в `pending_completion` («Отметить выполненным») → подтверждение Заказчиком (`completed`) → создание, редактирование и удаление отзыва с проверкой пересчёта рейтинга и счётчика заказов.
   - Негативные проверки: попытка откликнуться на собственный заказ, попытка оставить отзыв до завершения заказа.
3. На каждом шаге проверяй через `/browser`:
   - Ошибки в **Console** браузера (`TypeError`, uncaught exceptions).
   - Сетевые ответы в **Network** (ошибки `500`, некорректные `400`/`401`/`403`).
   - Сохранение состояния после перезагрузки страницы (`F5`).

### Шаг 3. Отчёт о тестировании
Выдай структурированный отчёт на русском языке:
- **Пройденные сценарии (✅ Passed)** — краткий список того, что проверено и работает корректно.
- **Найденные баги (🐞 Bugs)** — шаги воспроизведения, ожидаемый результат, фактический результат, HTTP-статус или ошибка из консоли браузера.
- **UX / UI замечания (💡 UX Notes)** — неудобства в интерфейсе или неинформативные сообщения об ошибках.
